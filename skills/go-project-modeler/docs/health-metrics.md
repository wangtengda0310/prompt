# 代码健康度/噪声度

## 能力说明

通过 6 个维度量化评估 Go 项目的代码质量，生成雷达图和热力图，快速定位问题区域。

## 六个评估维度

| 维度 | 权重 | 检测内容 | 关键指标 |
|------|------|---------|---------|
| 依赖复杂度 | 20% | 循环依赖、依赖深度、扇入扇出比 | 环路数量、最大深度 |
| 接口清晰度 | 20% | 接口方法数、0 实现的接口、鸭子类型 | 平均方法数、空接口占比 |
| 代码重复度 | 20% | 相似函数、重复结构体字段、copy-paste | 重复率百分比 |
| 结构复杂度 | 15% | 单结构体方法数、嵌套深度、圈复杂度 | 超大结构体数量 |
| 文件膨胀度 | 15% | 单文件行数、结构体数、函数数 | 膨胀文件列表 |
| 死代码率 | 10% | 未引用函数、未使用导出符号 | 死代码占比 |

## 输出格式

### 1. HTML5 交互页面
- **雷达图**：6 维度分数可视化，一眼判断健康状态
- **热力图**：文件级温度标记（15°C-100°C），红色区域需优先处理
- **噪音拓扑**：依赖关系着色（绿/黄/红/灰）

### 2. Mermaid + ASCII
- 节点着色（红/黄/绿）+ 内嵌评分表
- ASCII 文本热力图 + 温度标记（72°C / 🔥）

### 3. JSON
```json
{
  "chaos": 31,
  "noise": 0.12,
  "dims": {
    "dep": 85,
    "interface": 70,
    "duplicate": 90,
    "complexity": 60,
    "bloat": 75,
    "dead": 95
  },
  "worst_files": [
    {"path": "handler.go", "temp": 45, "issues": ["lines>500", "structs>3"]}
  ]
}
```

### 4. Summary
```
Chaos:31 Noise:12% Worst:handler.go(45°C)
Status: ⚠️ 关注 - 依赖复杂度偏高(56)
```

## 分级标准

| ChaosIndex | 等级 | 颜色 | 行动建议 |
|-----------|------|------|---------|
| 0-20 | 健康 | 绿色 | 保持 |
| 21-40 | 关注 | 黄色 | 监控 |
| 41-60 | 混乱 | 橙色 | 重构 |
| 61-100 | 失控 | 红色 | 紧急 |

## 调用示例

```bash
# 完整健康度仪表盘
/go-model -v health -f html

# 快速评分
/go-model -v health -f summary

# 只看依赖复杂度
/go-model -v health --dim=dep

# 生成 JSON 供 CI/CD 集成
/go-model -v health -f json -o health.json
```

## 数据来源

- **依赖复杂度**：`go mod graph` + 环路检测算法
- **接口清晰度**：`go/ast` 接口提取 + `go/types` 实现匹配
- **代码重复度**：Token 序列比对算法
- **结构复杂度**：`gocognit` 圈复杂度 + AST 遍历
- **文件膨胀度**：文件行数 + 结构体/函数计数
- **死代码率**：`go vet` deadcode 分析

## 计算公式

详细公式定义在 [Layer 2 文档](ref/health-formulas.md)，包括：
- 线性扣分函数：`max(0, 100 - (depth-4)*10)`
- 各维度评分算法
- 混乱指数计算

## 限制条件

- 需要 `go list` 成功（编译错误项目降级为低精度模式）
- 代码重复度分析需要完整 AST（Phase 2）
- 大型项目分析时间可能 >30s
